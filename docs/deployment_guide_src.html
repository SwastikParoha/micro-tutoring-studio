Putting {{ business }} online

A step-by-step guide to hosting the tutoring platform for free, on a link that stays up permanently — it never “falls asleep” and is not deleted after a month.

Two ways to do this. Pick one — you do not need both.
  • Option A — PythonAnywhere. Easiest by far. All done through a website, no black screen full of commands. About 20–30 minutes. Best if you are not technical. One small catch: the AI lesson-writing needs a paid add-on or a quick permission request (explained below); everything else — the parent portal, calendar, invoices, CRM — works fully on the free plan.
  • Option B — Oracle Cloud (Always Free). A little more setup (about an hour, involves typing commands). In return you get a proper small server that is free forever, with the AI features fully working and your own web address. Best if you want to set it once and never touch it.

Option A — PythonAnywhere recommended

1. Create the account

  1. Go to www.pythonanywhere.com and click Pricing & signup, then Create a Beginner account (the free one). No card needed.
  2. Pick a username — this becomes your web address, e.g. username brightsteps gives you brightsteps.pythonanywhere.com. Choose your brand name if it is free.
  3. Confirm your email.

2. Upload the code

From the PythonAnywhere dashboard, open a Bash console (Consoles → “Bash”). Type:

git clone https://github.com/YOURNAME/micro-tutoring.git
cd micro-tutoring

If your code is not on GitHub: on the Files tab, create a folder micro-tutoring and use Upload a file to add a zip of the project, then in the Bash console run cd micro-tutoring && unzip *.zip.

3. Install the app

python3.11 -m venv .venv
source .venv/bin/activate
pip install flask python-dotenv requests markdown jinja2 google-genai
python main.py setup      # downloads the Oak curriculum dataset (~40 MB)

Leave out weasyprint, playwright and crewai — they are heavy and the free plan has limited space. PDFs still generate (as clean printable HTML pages that any browser turns into a PDF with Print → Save as PDF).

4. Create the web app

  1. Go to the Web tab → Add a new web app → Manual configuration → Python 3.11.
  2. Under Code, set:
    • Source code: /home/USERNAME/micro-tutoring
    • Working directory: /home/USERNAME/micro-tutoring
  3. Under Virtualenv, enter: /home/USERNAME/micro-tutoring/.venv
  4. Click the WSGI configuration file link. Delete everything in it and paste:
import os, sys

path = "/home/USERNAME/micro-tutoring"
if path not in sys.path:
    sys.path.insert(0, path)

os.environ["BUSINESS_NAME"]   = "Your Brand Name"
os.environ["TUTOR_NAME"]      = "Your Name"
os.environ["ADMIN_USERNAME"]  = "you"
os.environ["ADMIN_PASSWORD"]  = "your-strong-password"
os.environ["SECRET_KEY"]      = "paste-a-long-random-string-here"
os.environ["GEMINI_API_KEY"]  = ""   # optional
os.environ["OAK_API_KEY"]     = ""   # optional

from wsgi import app as application

Replace USERNAME with your PythonAnywhere username everywhere, and fill in your five settings. Save the file.

5. Go live

  1. Back on the Web tab, click the big green Reload button.
  2. Visit https://USERNAME.pythonanywhere.com — you should see the sign-in page.
  3. Sign in with the admin username and password you set. You are live.
Your links are now:
Admin / tutor: https://USERNAME.pythonanywhere.com/admin
Families: https://USERNAME.pythonanywhere.com/parent — each family signs in and sees only their own child.
Keeping it permanent. The free plan asks you to press a “Run until 3 months from today” button on the Web tab every three months. PythonAnywhere emails you a reminder. One click keeps it running — the app and all your data stay exactly as they were. It is never deleted for inactivity the way Railway or Render free apps are.
About the AI features on the free plan. PythonAnywhere's free plan only lets the app talk to an approved list of outside websites, and Google's AI is not on it by default. So on the free plan:
  • The parent portal, calendar, attendance, invoices, reports editor, CRM and curriculum content — all work fully.
  • AI-written workbook notes and AI-drafted reports fall back to the built-in writer (still usable, just less tailored).
To switch the AI on, either (a) open a paid Hacker plan (about US$5/month) which removes the restriction, or (b) email PythonAnywhere support and ask them to add generativelanguage.googleapis.com to your allowed sites — they usually approve Google APIs for free accounts within a day.

Option B — Oracle Cloud Always Free

A real server that is free for life, with nothing blocked. You will type commands over a secure connection (SSH). Set aside an hour.

1. Create the free server

  1. Sign up at www.oracle.com/cloud/free. It asks for a card for identity only — the “Always Free” resources are never charged. Choose a home region close to you.
  2. In the console: Compute → Instances → Create Instance.
  3. Under Image and shape: choose Canonical Ubuntu 22.04, then shape Ampere → VM.Standard.A1.Flex with 1 OCPU and 6 GB memory (well inside the Always Free limit).
  4. Under Networking, tick Assign a public IPv4 address.
  5. Download the private key when prompted — you need it to log in. Click Create.
  6. When the instance is running, note its Public IP address.
  7. Open the firewall: Networking → Virtual Cloud Networks → your VCN → Security Lists → Default → Add Ingress Rules: source 0.0.0.0/0, protocol TCP, destination port 80. Repeat for port 443.

2. Connect and install

On your own computer, open a terminal (on Windows: PowerShell) and connect:

ssh -i path\to\your-key.key ubuntu@YOUR_PUBLIC_IP

Then, on the server:

sudo apt update && sudo apt install -y python3-venv python3-pip git nginx
sudo iptables -I INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -I INPUT -p tcp --dport 443 -j ACCEPT
sudo netfilter-persistent save

git clone https://github.com/YOURNAME/micro-tutoring.git
cd micro-tutoring
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
playwright install --with-deps chromium      # for polished PDFs
python main.py setup

3. Add your settings

Create the settings file:

nano .env

Paste this, fill it in, then press Ctrl+O, Enter, Ctrl+X:

BUSINESS_NAME=Your Brand Name
TUTOR_NAME=Your Name
ADMIN_USERNAME=you
ADMIN_PASSWORD=your-strong-password
SECRET_KEY=paste-a-long-random-string
GEMINI_API_KEY=your-key-or-leave-blank
OAK_API_KEY=your-key-or-leave-blank

4. Run it as a permanent service

sudo nano /etc/systemd/system/tutoring.service

Paste:

[Unit]
Description=Micro Tutoring
After=network.target

[Service]
User=ubuntu
WorkingDirectory=/home/ubuntu/micro-tutoring
EnvironmentFile=/home/ubuntu/micro-tutoring/.env
ExecStart=/home/ubuntu/micro-tutoring/.venv/bin/gunicorn wsgi:app -b 127.0.0.1:8000 -w 2 -t 120
Restart=always

[Install]
WantedBy=multi-user.target

Then:

sudo systemctl enable --now tutoring
sudo systemctl status tutoring        # should say "active (running)"

5. Put it on port 80

sudo nano /etc/nginx/sites-available/tutoring

Paste (replace the server name with your IP for now, or your domain later):

server {
    listen 80;
    server_name YOUR_PUBLIC_IP;
    client_max_body_size 25M;
    location / { proxy_pass http://127.0.0.1:8000;
                 proxy_set_header Host $host;
                 proxy_set_header X-Forwarded-For $remote_addr; }
}
sudo ln -s /etc/nginx/sites-available/tutoring /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

Visit http://YOUR_PUBLIC_IP/ — the sign-in page. Admin at /admin, families at /parent.

6. That is the server done

It now answers on http://YOUR_PUBLIC_IP/. To put it on your own web address with a padlock (HTTPS), do the “Using your own domain” section below.

Using your own domain

A cheap domain (£5–£10/year) is all you need to turn http://140.238.x.x/ into https://yourbrand.co.uk/admin. Buying the domain does not change the app — it is just two jobs: (1) point the domain at your server, and (2) tell the server its name so it can fetch a free HTTPS certificate.

This needs Option B (Oracle Cloud) or a paid PythonAnywhere plan. The free PythonAnywhere plan cannot use a custom domain — you would need their Hacker plan (about US$5/month), after which you add the domain under the Web tab and create the CNAME it shows you. The steps below are for the Oracle Cloud server.

1. Buy the domain

Use any registrar — Cloudflare, Porkbun and Namecheap are all cheap and fine. Avoid the “free for year one” upsells; a .com, .co.uk or .uk at the normal price is best. You do not need their hosting, email or “website builder” add-ons — just the domain.

2. Point the domain at your server

In the registrar's DNS settings, delete any placeholder records they added and create these two, using the Public IP address of your Oracle instance:

TypeName / HostValueTTL
A@ (the bare domain)your server's public IPAutomatic / 300
Awwwyour server's public IPAutomatic / 300

If you bought the domain at Cloudflare, set the two records to “DNS only” (grey cloud, not orange) so the server can manage its own certificate. Changes usually take 5–30 minutes to take effect (occasionally a few hours). Check progress at dnschecker.org.

3. Give the server a free HTTPS certificate (Caddy)

Caddy replaces nginx and fetches + renews a real certificate automatically. On the server:

sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy.gpg
echo "deb [signed-by=/usr/share/keyrings/caddy.gpg] https://dl.cloudsmith.io/public/caddy/stable/deb/debian any-version main" | sudo tee /etc/apt/sources.list.d/caddy.list
sudo apt update && sudo apt install -y caddy
sudo systemctl stop nginx && sudo systemctl disable nginx      # if you set nginx up earlier

Write the config (replace yourbrand.co.uk with your real domain):

sudo nano /etc/caddy/Caddyfile
yourbrand.co.uk, www.yourbrand.co.uk {
    reverse_proxy 127.0.0.1:8000
    request_body { max_size 25MB }
}
sudo systemctl restart caddy
sudo journalctl -u caddy -n 20      # should show "certificate obtained successfully"

4. Done

Open https://yourbrand.co.uk — the sign-in page, with a padlock. Your links are:

Tutor / admin: https://yourbrand.co.uk/admin
Families: https://yourbrand.co.uk/parent
Family sign-in link to send out: https://yourbrand.co.uk/

The certificate renews itself for free every ~90 days — nothing to do. If the padlock does not appear, wait for DNS (step 2) to finish propagating and run sudo systemctl restart caddy again. Make sure ports 80 and 443 are open in both the Oracle Security List and the server firewall (step 2 of Option B).

Giving families their login

  1. Register the child (admin → + Register pupil).
  2. Add them to the programme (Add to programme — set hours, rate, subjects).
  3. On the pupil's page, under Family login, click Create family login.
  4. A yellow bar shows the site link, username and password once — copy it and send it to the parent (text, email, WhatsApp). The password is not shown again; use Reset family password if they lose it.

The family signs in at /parent (or just your main link) and sees only their child: their plan, payments made and due, live “arrived / departed” status, the class timetable with self-service booking against your availability, and any reports you have marked sent.

Set your availability

Admin → Availability: add one row per bookable window (e.g. Monday 16:00–19:00). Families can only book classes inside these times, and only up to the number of classes in their monthly plan. You confirm attendance from the Calendar tab with the Arrived and Departed buttons.

Backups

Everything lives in one file: database/tutoring.db.

  • PythonAnywhere: Files tab → navigate to micro-tutoring/database → download tutoring.db. Do this weekly.
  • Oracle Cloud: on your computer, run scp -i your-key.key ubuntu@YOUR_IP:micro-tutoring/database/tutoring.db .

To restore, just put the file back in the same place and reload / restart.

Updating the app later

# PythonAnywhere: in a Bash console
cd micro-tutoring && git pull && source .venv/bin/activate && pip install -r requirements.txt
# then press Reload on the Web tab

# Oracle Cloud:
cd micro-tutoring && git pull && source .venv/bin/activate && pip install -r requirements.txt
sudo systemctl restart tutoring

Your database is never touched by an update — new columns are added automatically.

Troubleshooting

SymptomFix
“Something went wrong” on first load Check the error log (PythonAnywhere: Web tab → Log files; Oracle: sudo journalctl -u tutoring -n 50). Usually a typo in the WSGI file path or a missing pip install.
Sign-in page loops / “wrong password” The admin account is created from ADMIN_USERNAME / ADMIN_PASSWORD the first time the app runs. If you changed them afterwards, sign in with the old ones and change it on the Account page, or delete database/tutoring.db to start fresh.
Photo upload rejectedFiles must be under 25 MB and a normal image type (JPG, PNG, HEIC).
AI lessons show “off”Expected on PythonAnywhere free (see the note in Option A). On Oracle, check GEMINI_API_KEY is in .env and restart.
PDF looks like a plain web pageThe polished PDF engine is not installed (fine on free hosting). Open the page and use the browser's Print → Save as PDF — same result.
